# Repo map

Navigation only: where things live and who owns what. How it works is in the code, why in `ai/decisions/`.

## Repo

- `src/` — every source, and Vite's `root`. The pages sit at its top: `index.html` (`/`), `about.html`, `careers.html`,
  `security.html`. Each lists the partials it uses.
- `src/partials/sections/<page>/` — partials of a page section (`shared/` for those used by several pages);
  `src/partials/components/` — partials of a repeated element (a card, a list item). A partial is called by its path.
- `src/data/` — the data the partials render; each file exports one constant, wired in through `context` in `vite.config.js`.
- `src/styles/` — all CSS (below). `src/scripts/` — all JavaScript (below).
- `src/assets/` — `fonts/`, `images/`: referenced as `/assets/…`, bundled and hashed (below).
- `public/` — files that need a fixed URL, served as they are: `favicon.svg`, `apple-touch-icon.png`, `og-image.png` (the link preview).
- `vite.config.js` — Vite (`root: 'src'`, output `dist/` at the repo root) with `vite-plugin-handlebars`: the `partials`
  folder and `context(pagePath)`, which passes the current `page` and the
  `data/` constants, and the `eq` helper. The pages are listed in `build.rollupOptions.input`.
- `package.json` — scripts `dev`, `build`, `preview`, `format`, `format:check`, `lint`, `lint:fix`, `lint:css`, `lint:css:fix`, `size`;
  `package-lock.json` — the lockfile (npm, decision `npm-package-manager`). License: MIT, declared in `package.json` only
  (decision `license-in-package-json`).
- `.prettierrc`, `.prettierignore` — Prettier. `eslint.config.js` — ESLint, `.stylelintrc.json` — Stylelint (decision `linters`).
- `.size-limit.json` — limits on the built JS, CSS, font and images, checked by `npm run size` after a build.
- `.github/workflows/ci.yml` — GitHub Actions: the checks of `AGENTS.md` "Verification" on every push (decision `ci-size-limit`).
- `.husky/pre-commit` runs lint-staged (`.lintstagedrc.json`): ESLint and Stylelint `--fix`, then Prettier, on staged files.
- `vercel.json` — Vercel: clean URLs, the redirect from the old `/pages/…` links, the cache header of `/assets/`.
- `AGENTS.md` — the entry point for agents; `CLAUDE.md` points to it.
- `ai/` — agent docs: this map, `workflow.md`, `rules/`, `skills/`, `decisions/`, `prompts/`,
  `linear-task-template.md`, and the archive `superpowers/`.
- Build plugins, in `vite.config.js`, `build` only: `vite-plugin-image-optimizer` (sharp, SVGO) and an HTML minifier
  (`html-minifier-terser`). CSS has no setup: Vite's own lightningcss minify and target (decision `build-pipeline`).
- `dist/` — generated by `npm run build`; never edited.
- `.claude/worktrees/` — one git worktree per task when tasks run in parallel; ignored by git.

## Pages

- `index.html` — `shared/header`, `home/hero`, `home/products`, `home/cases`, `home/features`, `shared/faq`, `home/testimonials`, `shared/cta`, `shared/footer`.
- `careers.html` — `shared/header`, `shared/page-hero`, `careers/values`, `careers/benefits`, `careers/jobs`, `shared/faq`, `shared/cta`, `shared/footer`.
- `about.html`, `security.html` — only `shared/header` and `shared/footer` so far.
- No `404.html` source: the build copies `dist/index.html` to `dist/404.html` (a plugin in `vite.config.js`); Vercel serves it
  with status 404 for an unknown path.
- Every page's `<head>` is `shared/head`: the stylesheet, the script, the meta and social tags.

## Partials (`src/partials/`)

- `sections/shared/head` — the `<head>` content of every page, built from `page` and `site`.
- `sections/shared/header` — the logo link, navigation (`navigation` as a loop, `aria-current` from `page`), the mobile menu button.
- `sections/shared/footer` — the logo link, navigation like the header, `contacts`, the bar with `socials` and legal text, the author line.
- `sections/home/hero` — the first screen of home. `sections/shared/page-hero` — the hero of Careers, About and Security: one context, `page.hero`.
- `sections/home/products` — the audience switch (For Individuals / For Businesses) and two panels of `product-card`.
- `sections/home/cases` — Use Cases: `caseItems` as `case-item`.
- `sections/home/features` — category tabs: `featureGroups` as tabs, panels of `feature-item`.
- `sections/shared/faq` — the FAQ: `groups` (the default set is `questionGroups`) as `question-item`, the rest under an expander; `name` makes its ids unique.
- `sections/home/testimonials` — the audience switch and two panels, each a `testimonial-carousel`.
- `sections/shared/cta` — the call-to-action card of Home and Careers: one context, an entry of `cta` (title parts, text, `button`).
- `sections/careers/values` — Our Values on Careers. `sections/careers/benefits` — Our Benefits: `benefits` as `icon-card`.
- `sections/careers/jobs` — Job Openings: `jobs` as `job-card`; the Apply Now link is a `mailto:` built in `data/jobs.js`.
- `components/section-heading` — a section's title (one accent word), text (an optional link at its end) and an optional right slot (the toggle).
- `components/` — `product-card`, `case-item`, `feature-item`, `question-item`: data comes as hash parameters or from `each`.
- `components/icon-card` — an icon circle left of an `h3`, text under it (`icon`, `title`, `text`; flag `inset` for the Security card).
- `components/badge` — a "Label: value" pill (`label`, `value`); `components/job-card` — a vacancy: badges, About, a requirements list, Apply Now.
- `components/currency-converter` — the hero card's Money Exchange: two native selects, an amount, the result, Exchange.
- `components/testimonial-carousel` — arrows and a scroll-snap track of quote cards (`items`, `label` as parameters).

## Data (`src/data/`)

- `case-items.js` → `caseItems`, `feature-groups.js` → `featureGroups`, `question-items.js` → `questionGroups`,
  `products.js` → `products`, `values.js` → `values`, `benefits.js` → `benefits`, `jobs.js` → `jobs`, `hero-transactions.js` → `heroTransactions`,
  `testimonials.js` → `testimonials` (text, name and the "N of M" `position` per audience),
  `currency-rates.js` → `currencies` (code, name, icons, rate per 1 USD, decimals; the fixed rates, decision `fixed-rates-native-select`).
- `cta.js` → `cta` (the `home` and `careers` entries of the CTA).
- `contacts.js` → `contacts`, `socials.js` → `socials`, `footer.js` → `footer` (copyright, legal documents, author name).
- `navigation.js` → `navigation` (the menu links); `pages.js` → `pages`: `path`, `title`, `description`, `navKey`, `hero` (page-hero pages), per page file name.
- `site.js` → `site` (name, the production origin, theme colour, the preview image: its size and alt).

## Styles (`src/styles/`)

- `style.css` — imports the files below in order: `general`, `ui`, `components`, `sections`.
- `general/` — `reset.css`, `fonts.css` (`@font-face`), `variables.css` (every token), `main.css` (`body`, focus ring, `.container`, `.section`).
- `ui/` — the shared elements: `button.css`, `toggle.css` (the Individuals / Businesses pill), `visually-hidden.css` (text for assistive technology only).
- `components/`, `sections/` — one stylesheet per partial of the same name.

## Scripts (`src/scripts/`)

- `main.js` — the only entry (the pages load it): finds each section's root, creates its controller, calls `start()`.
- `constants.js` — the media queries (equal to the CSS breakpoints), key names, button texts, state classes.
- `components/` — reusable widgets: `Tabs` (ARIA tabs: arrows, `Home`/`End`, orientation by width), `Toggle` (`aria-pressed`
  buttons and `hidden` panels), `Disclosure` (`aria-expanded`, `inert`, the height as a custom property), `CurrencyConverter` (reads the rates from the
  options' `data-*`; `main.js` creates it directly, no controller), `Carousel` (scroll-snap track: arrows scroll by one card, disabled at the ends).
- `controllers/` — one class per section: `HeaderMenuController` (the mobile menu: `inert`, `Escape`, close on a link), `FooterController` (the current year),
  `ProductsController` (`Toggle`; also selects the tab named by a `#products-<key>` address and scrolls to the section), `FeaturesController` (`Tabs`), `FaqController` (`Disclosure`), `TestimonialsController` (`Toggle` and a `Carousel` per panel).
- Hooks are `data-*`: section roots `data-header`, `data-footer`, `data-products`, `data-features`, `data-faq`, `data-testimonials`, the converter `data-currency-converter` (`ai/rules/oop.md`).

## Assets (`src/assets/`)

- `fonts/` — the self-hosted Lexend `woff2`. `images/` — `logo.svg`, the Careers hero photo, `icons/`, `decor/`, `flags/`.
- Referenced by the root path (`/assets/images/…`) in HTML, `data/` and CSS; the build emits each once, hashed.

## Where is the recipe

- A page section or a repeated element: `ai/skills/section.md`. Reviewing a diff: `ai/skills/review.md`.
- Colours, type, spacing, components and the sections of each page, as designed: `ai/design-system.md`.
- What must hold: `ai/rules/`. Why it is so: `ai/decisions/` (index in its `README.md`).

## Deployment

Live at <https://banking-coral-three.vercel.app> on Vercel through its Git integration: `main` is production, other
branches get previews; the config is `vercel.json` only (decision `clean-urls-vercel-json`).

## Not in this project

- No UI framework, TypeScript, CSS preprocessor or backend: decision `vanilla-js-vite-handlebars`.
- No automated tests: decision `no-automated-tests`. No pull requests: decision `local-merge-without-pr`.
- No Login or Sign Up pages: decision `four-pages-no-auth`. No external currency API: `ai/rules/scope.md`.
