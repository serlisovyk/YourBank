# Plan: meta and link previews (MY-202)

Goal: every page gets its own title, description, canonical URL, favicon, theme colour, Open Graph
and Twitter tags from one head partial; the whole site shares one preview image. The spec is
`ai/superpowers/specs/2026-10-24-meta.md`. No open questions.

## Changes

- `partials/sections/shared/head.html` holds the whole `<head>` content (charset, viewport, the
  stylesheet, the script entry, the metadata); each page is `<head>{{> sections/shared/head }}</head>`.
  It sits beside `header` and `footer`: shared page chrome, not a section.
- `data/site.js` → `site`, wired into `context`: `name`, `url` (the production origin, the only place
  it is written), `themeColor` (`#1A1A1A`, the `--grey-10` token) and the preview `image`
  (`src`, `width`, `height`, `alt`). The head builds absolute URLs as `{{site.url}}{{page.path}}` and
  `{{site.url}}{{site.image.src}}`; no template logic beyond that.
- `data/pages.js`: every entry gets `path` (`/`, `/careers`, `/about`, `/security`: clean URLs, no
  `.html`) and a unique `title` and `description`. About and Security are not built yet; their text
  is written from what the pages will hold (About: mission, vision, press releases; Security: how
  accounts are protected, the FAQ), so it does not change when the content lands. A new page is a
  record in `data/pages.js` with these fields.
- Tags: `description`, `canonical`, `theme-color`, `icon` (SVG), `apple-touch-icon`; `og:site_name`,
  `og:title`, `og:description`, `og:url`, `og:type=website`, `og:image` (absolute), `og:image:width`,
  `og:image:height`, `og:image:alt`; `twitter:card=summary_large_image`, `twitter:title`,
  `twitter:description`, `twitter:image`. `og:title` / `og:description` repeat the page's `title` /
  `description`; `og:url` equals the canonical.
- `public/` appears (the map says it is created with its first file): `favicon.svg`,
  `apple-touch-icon.png` (180×180) and `og-image.png` (1200×630). They need fixed URLs: the
  crawlers cache the absolute `og:image` URL and the browsers ask for the icons by name, so the
  hashed `/assets/` pipeline does not fit (`ai/rules/assets-performance.md` allows `public/` for
  that). No `favicon.ico`, no manifest.
- Favicon: the diamond mark of `logo.svg` (lime) on a rounded `#1A1A1A` square, so it reads on a light
  tab too. `apple-touch-icon.png`: the same square without the rounding (iOS rounds it), rendered
  once with `sharp`.
- `og-image.png`: a screenshot of the Home first screen of the current build (headless Chrome at 1440
  px wide, cropped to the 1.9:1 ratio and resized to 1200×630 with `sharp`), PNG, under 300 kB. The
  generated files are committed, the generator is not.
- Caching: `vercel.json` sets the immutable header on `/assets/` only, so the files in `public/` keep
  Vercel's default (revalidated on each request); no change. A replaced preview image is picked up
  by a scrape once the platform's own cache expires; a new file name is never needed.
- 404: `dist/404.html` is a byte copy of Home, so it carries Home's canonical and `og:url`. Accepted:
  an error page is never shared or indexed, and a second head would break the copy.
- Local preview and dev: the absolute URLs point at production, which is intended (they are only
  read by crawlers).

## Docs

- `ai/rules/html.md`: a new page is a record in `data/pages.js` with its meta; the head is the partial.
- `ai/rules/architecture.md`: the new-page line names `path`.
- `ai/rules/assets-performance.md`: two lines under "Page metadata" (absolute URLs from `site.url`; the preview image). The `public/` line stays
  as it is.
- `ai/map.md`: the head partial, `site.js`, the `public/` files, the pages line.
- `ai/decisions/`: a record, `2026-10-24-link-previews.md`: the origin and the preview image are
  fixed by hand, in `public/`; rejected: a hashed image, a generated image at build time.

## Verification

`npm run lint`, `lint:css`, `format:check`, `build`, `size`, `cmp dist/404.html dist/index.html`. The
`<head>` of each built page read for its own title, description, canonical and `og:url`. The OG image
checked for 1200×630 and its weight (it is in `public/`, so outside the `dist/assets/*` size globs).
`npx vite preview`: the favicon shows, the console is clean. On production after the merge: an Open
Graph checker, a Telegram preview.

## Left out

- `robots.txt`, `sitemap.xml`, `llms.txt`, JSON-LD (MY-203); the About and Security content.
