# Plan: the CSS as the author writes it (MY-214)

Goal: the stylesheets read the way the author writes CSS, with no visual change. No spec: nothing
observable changes, a diff of screenshots and of every element's box before and after is the test.
Records touched: `breakpoint-scheme` (the fluid formula), `linters` (the class pattern),
`touch-targets-hit-area`, `reveal-on-scroll` (its tokens), `ci-size-limit-css-room` (the CSS must not
grow past 8.5 kB gzip; this change should shrink it).

## Changes, in commit order

1. **`background` longhands.** No `background:` shorthand anywhere in `styles/`: `background-image`,
   `-position`, `-size`, `-repeat`, `-color`. `.icon-card--inset` needs `background-image: none` to stay
   flat. `transition: background` names `background-color`.
2. **One-side spacing.** `padding-left: X`, not `padding: 0 0 0 X`; `padding-inline` / `padding-block`
   for an axis; `margin-top` + `margin-bottom` for the two sides of `margin`; `border-left`, not
   `border-width: 0 0 0 1px`; `inset-inline` + `bottom`, not `inset: auto 0 0`. A two-value
   `padding: Y X` on both axes stays.
3. **Plain grid.** `repeat(2, 1fr)`, `1fr auto 1fr`, `664fr 932fr` instead of `minmax(0, …)`; a
   `min-width: 0` on an item only where a column would grow past its share.
4. **Few tokens (with 5).** `variables.css` keeps the palette, the font, radii, the documented type
   scale and the values two or more stylesheets use. A value used once is written in its stylesheet; a
   value used twice or more inside one block is a custom property on that block's root rule. The
   reveal values move into `ui/reveal.css`, the focus ring and the content width into `general/main.css`.
5. **Readable fluid values (with 4).** The design is exact at 390, 1440 and 1920. Three shared lengths in
   `variables.css` run 0 → 1px over their segment: `--ramp-390-1440`, `--ramp-1440-1920` and
   `--ramp-768-1440` (the Security panel). A value is its size at 390 plus the growth of each segment,
   written with the design numbers:
   `calc(28px + (38 - 28) * var(--ramp-390-1440) + (48 - 38) * var(--ramp-1440-1920))`; a flat segment
   is left out. No second copy of a token, so a value can sit next to the rule that uses it. The one
   `@media (width < 1440px)` stays, in `variables.css`, and sets the two ramps that end at 1440 to 1px
   from 1440 up: `vw` leaves out the stable scrollbar gutter and the query does not, so without it a
   1440 wide window with a scrollbar would get the sizes of 1425. Two values have other anchors (the
   toggle's padding from 320, the Mission overlap from 880) and write their own ramp in their stylesheet.
   A new decision record supersedes `breakpoint-scheme`; the old one only changes its Status line. Each
   token is checked in the browser, old build against new, every 5 px from 320 to 1920.
6. **The hero card in `em`.** `.hero__content` takes a `font-size` of the card width / 515 * 16:
   16px when the card is 515 wide, as drawn. Sizes of the card and the two pills are `em` of the design
   px / 16 (padding 14 → `0.875em`). `--hero-unit` goes. `--text-hero-small` and `--text-hero-tiny`
   keep the 12px floor, as `max(12px, 1em)` and `max(12px, 0.875em)`. An element that sets its own
   `font-size` cannot use `em` for its own spacing: the transactions title's and the converter title's
   bottom margin move to the box that follows them, the converter button's padding relies on its 44px
   `min-height` where the floor applies, the amount cell's vertical padding is written from the card
   width. The card's own padding, the icon sizes and the cell padding stay separate fluid values.
7. **Stylelint.** `selector-class-pattern` becomes `^[a-z][a-z0-9-]*(__[a-z0-9-]+)?(--[a-z0-9-]+)?$`,
   with the message and `resolveNestedSelectors` as they are.
