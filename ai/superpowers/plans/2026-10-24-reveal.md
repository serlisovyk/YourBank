# Plan: reveal on scroll (MY-205)

Goal: the sections and cards fade in when they scroll into view. Behavior is in
`ai/superpowers/specs/2026-10-24-reveal.md`. No open questions: the choices below are final.

## Decisions made in this plan

- **One `Reveal` component per page, created from the `SECTIONS` table.** It owns `<main>`
  (`data-reveal-root`) and one `IntersectionObserver` for every `[data-reveal]` inside; like
  `CurrencyConverter`, it needs no controller (`ai/rules/oop.md`). A page start outside the table
  would be a second way to wire; the root is one element per page, so the table fits.
- **Opt-in by `data-reveal`** (`ai/rules/style.md`: a hook is a `data-*`). It sits on the root of a
  component that always lies below the first screen (`section-heading`, `product-card`, `case-item`,
  `feature-item`, `question-item`, `icon-card`, `job-card`, `press-card`, `testimonial-carousel`),
  and on the section-owned elements: the Products divider, a value, a Mission and Vision row, the CTA
  card. The hero partials never carry it. Rejected: a selector list in the script (the script would know
  the sections); revealing whole sections (one block fading, no cascade, a tall section needs
  a threshold that always fires).
- **The hidden state exists only behind a class on `<html>` that the script sets** (`js-reveal`), so
  no script means a complete page (decision `reveal-on-scroll`). The script is a deferred module,
  so the class cannot be set before the first paint; instead `start()` marks what is already in
  view or above it as revealed **before** adding the class, so nothing that was drawn ever hides
  and shows again. No inline script in `<head>` (`ai/rules/assets-performance.md`: one script).
- **Reduced motion: `start()` returns early** when `(prefers-reduced-motion: reduce)` matches, so the
  class is never added and nothing is hidden. `general/reset.css` still shortens every transition to
  0.01 ms, which keeps the two agreeing if the setting changes mid-visit. No `prefers-reduced-motion`
  block in the reveal stylesheet (`ai/rules/css.md`).
- **The observer always fires:** `threshold: 0` (one pixel is enough, a tall element needs no ratio)
  and `rootMargin: 0px 0px -10% 0px`, so an element appears once its top is 10% of the window above the
  bottom edge. A hidden panel has no box and fires when it is shown; the rest of the FAQ, clipped by
  its collapsed region, fires when the region opens.
- **Cascade from the batch, not from markup:** the elements of one observer callback get an index in
  DOM order, written as the number `--reveal-index` (capped at 4); CSS turns it into a delay with
  `--reveal-step`. A single card scrolled in alone has no delay.
- **Focus:** a `focusin` listener on the root reveals the element that holds the focus and unobserves
  it; in CSS `:focus-within` lifts the hidden state with `transition: none`, so the focused element is
  fully visible in the same frame, not after a fade.
- **CSS: one stylesheet `ui/reveal.css`**, one rule set on `[data-reveal]` for every page, tokens
  `--reveal-duration` 0.5 s, `--reveal-easing` an ease-out, `--reveal-offset` 20 px, `--reveal-step`
  0.08 s in `variables.css`. Only `opacity` and `transform`.
- **Rejected:** `animation` with `@keyframes` (a one-way state is a transition); `will-change`
  (a permanent layer per card for a one-off fade); an observer per element; a library.

## Verification

`npm run lint`, `lint:css`, `format:check`, `build`, `size` (the CSS has about 0.17 kB gzip left under
8 kB: if the limit would be crossed, stop and report the numbers, not raise it); `dist/404.html` equals
`dist/index.html`. `vite preview` and headless Chrome over CDP at 1920 and 390 px on the four pages:
every `[data-reveal]` ends at opacity 1 after scrolling to the bottom; `prefers-reduced-motion:
reduce` (nothing hidden, no transition); script execution disabled (everything visible); Tab from
the top never focuses an element of opacity below 1; CLS on Home before and after; axe-core with 0
violations on the four pages after scrolling; the Products and Testimonials toggles, the Features
tabs and the FAQ expander still work and reveal what they show.
