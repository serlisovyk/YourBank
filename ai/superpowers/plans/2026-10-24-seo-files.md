# Plan: SEO files and structured data (MY-203)

Goal: `robots.txt`, `sitemap.xml`, `llms.txt` and a JSON-LD `Organization` on Home. No UI changes, so
no spec. No open questions. Page `<head>` meta, canonical, Open Graph and the favicon are MY-202.

## Base URL

The site has no URL in `data/` yet. `src/data/site.js` exports `site` (`name`, `url`:
`https://banking-coral-three.vercel.app`, no trailing slash); the JSON-LD builder reads it. A custom
domain later means changing `site.url` and the absolute URLs in the three static files below.

## Static files in `public/` (fixed URLs, copied as they are)

- `robots.txt` — `User-agent: *`, `Allow: /`, `Sitemap:` with the absolute URL.
- `sitemap.xml` — hand-written: four `<url>` entries (`/`, `/careers`, `/about`, `/security`; clean,
  absolute, no `.html`, no trailing slash except the root), each with `lastmod`.
- `llms.txt` — llmstxt.org shape: an H1, a blockquote summary (says it is a portfolio demo of a
  fictional bank, built from a third-party design template, without naming it), one `## Pages`
  list with one line per page described by purpose, and an `## Optional` link to the source code.
- `logo.svg` — a copy of `assets/images/logo.svg` on a `#1a1a1a` square (the page background): the
  source logo has white lettering and would vanish on the white card of a search result. The source
  logo is hashed under `/assets/`, and a hashed URL changes with the logo and 404s after a deploy,
  so structured data needs a fixed one (`ai/rules/assets-performance.md`: `public/` is for a file
  that needs a fixed URL).

## Sitemap: hand-written, not generated

Four pages that rarely change, and a new page is already a deliberate act (`four-pages-no-auth`:
the author asks). A generating plugin needs per-page `path` and `lastmod` in `data/pages.js`, a
`closeBundle` writer in `vite.config.js`, and still has no honest `lastmod` (build time lies, git
time needs a git call in the build). That is more config for a file that stays correct with one
added line, and `ai/rules/html.md` gets the line "a new page goes into `sitemap.xml` and
`llms.txt`". Rejected: the plugin. The `Sitemap:` line, the sitemap and `llms.txt` repeat the
absolute origin; that is the price of static files and is recorded in the decision.

## JSON-LD on Home

- Type `Organization`, not `BankOrCreditUnion`: that type inherits `LocalBusiness`, for which Google
  expects a postal `address`, and the footer has only "Somewhere in the World". Organization has
  no required fields and still carries the logo, contacts and `sameAs`.
- `src/data/structured-data.js` exports `organizationJsonLd`, a `JSON.stringify` string built from
  `site`, `pages.index.description`, `contacts` (the `mailto:` and `tel:` entries, found by prefix, not
  by index) and `socials` (`sameAs`). Nothing is copied from the footer data.
- `vite.config.js`: one new `context` key, `organizationJsonLd`. Home's `<head>` renders it raw:
  `<script type="application/ld+json">{{{organizationJsonLd}}}</script>` (triple braces: double
  braces would HTML-escape `&` and quotes, which a script body does not decode).
- The HTML minifier does not touch script bodies (no `minifyJS`); verified on the build.
- `sameAs` carries the footer's social links as they are (the networks' home pages today); real
  profile URLs are a data change, not a code one.

## Hosting

`cleanUrls` only strips `.html`; `.txt` and `.xml` are served by extension as `text/plain` and
`application/xml`. Checked locally with `npm run preview` and `curl -I`; production after the merge.
The 404 stays a copy of home (`cmp dist/404.html dist/index.html`).

## Docs

- `ai/rules/assets-performance.md` and `ai/rules/scope.md`: "no sitemap unless the author asks"
  becomes the manifest only; `public/` lists what it holds.
- `ai/rules/html.md`: a new page goes into `sitemap.xml` and `llms.txt`.
- `ai/map.md`: `public/` contents, the two data files, the Home JSON-LD.
- A decision record `seo-files-in-public` and its index line.

## Verification

`npm run lint`, `lint:css`, `format:check`, `build`, `size`; `cmp dist/404.html dist/index.html`;
`dist/robots.txt`, `dist/sitemap.xml` (parsed as XML), `dist/llms.txt`, `dist/logo.svg` exist; the
JSON-LD in `dist/index.html` parses with `JSON.parse` and appears on Home only; `npm run preview`
and `curl -I` for the content types; Home still renders (no visual change).

## Left out
